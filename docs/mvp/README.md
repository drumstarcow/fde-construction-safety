# MVP · 最小可运行产品

> 要求第 5 条：「完成一个最小的 MVP —— 上传 github 项目仓的 docs 中」。
> 本目录是 MVP 的副本，源码主目录在仓库根 `src/safety_backend/`、前端在 `web/`。

## 它是什么

施工隐患与整改闭环的**协同助手**：围绕一笔业务核对来源，生成待人工复核的交接清单。
不自动批准、不写业务系统、不判定安全合格。

## 三条标准（平台对 MVP 的定义）

| 标准 | 本项目的数 |
|---|---|
| 知识库 ≥30 条 | **49 条**（5 个主题，每条带来源编号） |
| 知识图谱可视化 | **89 节点 / 278 关系**，可按关联层数展开子图 |
| 带依据问答 | 回答末尾附引用条目编号与来源；检索不到直说没有 |

## 两种跑法

### A. 零依赖（推荐上课演示）

双击 `mvp-demo.html` 即可，浏览器打开就有五个页签：
业务工作台 / 知识和图谱 / 证据与引用 / 执行与审计 / 场景评估。
数据内置（20 笔合成业务），不需要 Python、不需要网络。

### B. 连真后端

```bat
pip install -r requirements.txt
py -m uvicorn app:app --port 8010 --app-dir src/safety_backend
```

然后双击 `index.html`，左上角后端地址填 `http://127.0.0.1:8010`。

## 接口（11 个）

见 [../api.md](../api.md)。核心四个：

- `POST /api/run` 跑三步编排（范围核对 → 资料版本核对 → 草稿起草）
- `POST /api/search` 检索并返回引用
- `GET /api/graph?focus=K22&layers=1` 图谱子图
- `GET /api/eval` 五个评估集的实测结果

## 演示时说什么（三句）

1. 「痛点是凭证链断了，不是识别不出隐患。」
2. 「规则先做、模型补缝——模型只出草稿，判定必须是人。」
3. 「49 条知识、89 个节点，回答必带引用。」

## 已知限制

- 模型层未接生产模型（`/api/health` 返回 `degraded:true`），当前为规则 + 人工形态。
- 合成样本 100 笔、真实脏数据比例未知。
