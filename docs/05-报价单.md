# 报价单 · 施工隐患与整改闭环协同助手（基础费 + 效果浮动）

客户：远筑工程（合成训练场景）　编制日期：2026-11-02　有效期：30 天

## 〇、计价方式与理由

本报价**不用人天计价**，采用「**基础费 + 效果浮动**」。

理由只有一条：**人天计价下客户算不出自己赚了多少**。AI 项目里客户一定会问“这套东西替我挣回了多少人力”，人天回答不了这个问题，只能被压价。而我们的价值恰好是可量化的——处理时长、返工次数、超期率本来就是项目基线里已在测的指标（f00、f53）。

**计价的判断标准**：客户能不能用这个价算出自己赚了多少。能算，才谈得上高价值定价。

## 一、基础费（交付能力 + 确定性交付物）

**基础费：78,000 元**（含税），覆盖从调研到试点验收的全部工作，分期支付。

| 阶段 | 交付物 | 验收标准 | 金额 |
|---|---|---|---:|
| 一、调研与基线 | 业务机会清单、指标基线、项目章程 | 基线在试点区单独取数、分母与统计周期固定（f53） | 14,000 |
| 二、规则层 | 关联 / 去重 / 版本校验 + 单元测试 | 历史回放 100 条，可自动关联率 ≥80%（REQ-01） | 22,000 |
| 三、编排与知识库 | 三步编排、49 条知识、图谱 278 关系、语义检索 | 每个回答带条目编号与来源（f45） | 18,000 |
| 四、前端与审计 | 五页面、审计六字段、七类异常 | 未确认导不出交接单；越权必拒并留痕（f41） | 16,000 |
| 五、试点与交接 | 操作手册、培训、交接清单、源码与文档 | 两家分包试点通过、重大隐患升级完整率 100%（f02） | 8,000 |
| **合计** | | | **78,000** |

## 二、效果浮动（按可验证的业务结果付费）

浮动部分**不设上限**，但设**封顶系数**：最高不超过基础费的 50%，即 **39,000 元**。

| 指标 | 基线 | 目标 | 计量口径 | 达成奖金 |
|---|---|---|---|---:|
| 照片自动关联率 | 0%（现状靠人工核对，f10） | ≥80% | 回放 100 条历史隐患，可关联占比 | 12,000 |
| 复查等待时长 | 3 天（f00） | ≤1 天 | 上报→复查完成，试点区单独取数 | 10,000 |
| 超期隐患率 | 24%（f00） | ≤8% | 超期未整改 / 当期总数，按月 | 8,000 |
| 返工次数 | 未测（f01 待补） | 下降 ≥30% | 退回重报 + 分包侧重新联系，双口径（f51） | 6,000 |
| 交接一次成功率 | 未测 | ≥90% | 未确认不得标记完成（f23） | 3,000 |

**为什么客户算得出来**：

> 复查等待从 3 天降到 1 天，按日均 70 条隐患（f12）计，每年少盖约 2 个专职复核岗的工时；超期率从 24% 降到 8%，按每月 2100 条计，每年减少约 4000 条超期隐患的停工与整改风险。这两笔账客户自己能算，奖金才有说服力。

## 五、为什么不用另外几种计价

| 方式 | 不采用的理由 |
|---|---|
| 人天 / T&M | 客户算不出赚多少，AI 时代最易被压价；且本项目范围已在阶段一冻结 |
| 功能点 / 规模 | 需要权威标准支撑，争议成本高；本项目不是标准产品包 |
| 固定总价 / 整包 | 前期可行，但把验收风险全压在交付方；本项目指标波动受客户侧流程影响大 |
| 订阅 / 年费 | 首期不适用（还在试点），二期可转年费制 |
| 纯用量计费 | 成本不可控，须做封顶；本项目以业务结果而非调用量为价值锚点 |
| **基础费 + 效果浮动** | **采用**：基础费保交付，浮动部分把双方利益绑定在同一组指标上 |

## 六、成本承担与风险（不含人天口径）

本项目对客不以人天计价，但内部必须知道成本边界在哪，否则定价就是拍脑袋。这里只写结论，不写人天拆解。

**内部投入折算低于基础费。** 基础费 78,000 元覆盖从调研到试点验收的全部交付；若各项指标全部达标，加上效果奖金共 117,000 元，覆盖内部投入后仍有合理毛利。

**风险是主动承担的**：若试点期满、指标未达标，我们只收基础费 78,000 元——此时毛利被压薄甚至亏损。这是选择「效果浮动」必须付的代价，用来换取客户对结果计价的信任。

**因此只在三个前提下报价**：
1. 指标可测——基线在试点区内单独取数、固定分母与统计周期（f53）；
2. 可归因——客户方流程在试点期不发生重大变更，否则重新议定基线；
3. 有停止条件——触及「建议当结论 / 未签核即销项 / 覆盖原记录」任一，暂停试点并复盘（f40、f42），此时按下阶段结算，不计奖金。

**为什么不写人天**：人天计价让客户算不出收益，2026 年已被主流压价；把成本拆成“开发 8 人天”这类话，等于主动把价值锚点交给对方的砍价表。成本我们自己心里有数即可。

## 七、假设与除外

- 假设：客户提供历史样本、字段归属确认人、两家分包配合；接口保持只读（f32）。
- 除外：写接口开发与授权、等保测评、硬件与云资源、跨厂区推广。
- **效果浮动的前提**：基线必须在试点区内单独取数、固定分母与统计周期（f53）；若客户方流程同期发生重大变更，双方需重新议定基线。

## 八、未核实项（影响报价的七条）

1. 主编号来源与照片关联字段（f33）→ 影响规则层开发工作量，需预留一档缓冲
2. 是否存在写回接口（f32 当前只读）→ 若有，规则层与审计的工作量需各增一档
3. 真实环境的照片缺时率与重复工单率（f01 未量）→ 影响基线测量与回放样本量
4. 人工复核成本计入项目还是运维（f03）→ 影响效果浮动的归因口径
5. 各岗位升级时限数值未定 → 影响异常兜底实现
6. 留存期限（f43 暂定 90 天）→ 影响审计存储与运维成本
7. 试点是否锁定两家分包（f02）→ 若扩到全现场，基础费上调约 30%
