# 设计说明

> 完整方案见 [04-方案设计.md](04-方案设计.md)。本文是一页版索引。

## 一句话

做的是「**凭证链 + 交接闭环**」，不是「识别隐患」。客户不缺能拍照的工具，缺的是
「这条隐患的整改证据能不能站住、算不算完成」。

## 四层结构

```
界面层   业务工作台 / 知识和图谱 / 证据与引用 / 执行与审计 / 场景评估
编排层   ① 项目范围核对 → ② 资料与版本核对 → ③ 交接草稿起草
能力层   规则引擎（确定性） | 模型层（可降级） | 知识检索（BM25 + 图谱扩展）
数据层   隐患台账 / 照片元数据 / 单据版本 / 状态日志 / 知识库 / 审计日志（只读接入）
```

## 三个关键取舍

1. **规则先做、模型补缝**：规则命中即出结果，不经过模型；模型只做疑难相关性判断与
   草稿起草，输出一律标「建议」。理由是判定出错属安全责任，关联出错只是多核对一次。
2. **两套完成口径并列、不合并**：分包按上传照片、监理按现场复查，系统如实记录两套，
   交总监裁定。技术能做的到此为止。
3. **人工卡点是真卡点**：未确认的交接单导不出。这条曾被外部评审测出「只写在文档里」
   （`/api/run` 返回草稿但不落库，`/api/confirm` 直接 404），修复后复测通过。

## 红线

不自动销项 · 不判定安全合格 · 不写业务系统 · 不覆盖原始记录 · 不借用账号 · 不接未授权接口。
