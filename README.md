# 施工隐患与整改闭环 · 协同助手

> FDE（Forward Deployed Engineer）全流程训练项目：从业务挖掘走到构建交付的完整一单。
> 客户：远筑工程（合成训练场景）｜课程：开源创新思维微专业 · 期末项目

## 一句话

客户的痛点不是「想用 AI」，是**凭证链断了**——整改照片对不上原隐患、分包与监理对「完成」有两套定义。本项目做一个**协同助手**：围绕一笔业务核对来源，生成**待人工复核的交接清单**，不自动批准、不写入业务系统。

## 这个项目解决什么

| 现象 | 后果 | 我们的做法 |
|---|---|---|
| 整改照片无法挂回原隐患 | 巡查员反复跑现场核对 | 规则优先做关联，模型只补疑难；可自动关联率 84%（阈值 80%） |
| 照片缺时间与位置 | 同一隐患重复上报形成重复工单 | 缺元数据直接进人工修复队列，不猜补 |
| 分包按上传照片算完成、监理按现场复查算完成 | 指标虚高、返工 | 两套口径并列记录、不合并，交总监裁定 |
| AI 建议被当成结论 | 安全责任无法追溯 | 模型只出草稿，签核必须是人 |

## 架构一览

```
界面层   业务工作台 / 知识和图谱 / 证据与引用 / 执行与审计 / 场景评估
编排层   ① 项目范围核对 → ② 资料与版本核对 → ③ 交接草稿起草
能力层   规则引擎（确定性优先） | 模型层（可降级） | 知识检索（BM25 + 图谱扩展）
数据层   隐患台账 / 照片元数据 / 单据版本 / 状态日志 / 知识库 / 审计日志（只读接入）
```

**核心取舍：规则先做，模型补缝。** 规则命中即出结果，不经过模型；模型只做两件事——疑难记录相关性判断、交接草稿起草。输出一律标「建议」，不参与判定。

**为什么 core 里再分三块**：规则、模型、编排的失败模式完全不同——规则出错是「多核对一次」，

一条结论是谁给的。

## 环境要求

- Python **3.11+**
- 无需数据库、无需 Node
- 模型 key 可选：没有 key 时自动降级为「规则 + 人工」，全流程仍可跑通

## 安装与启动（Windows 命令）

```bat
cd 项目目录
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt

rem 可选：配置模型（不配也能跑）
copy .env.example .env
rem 编辑 .env 填入 CLOUD_API_KEY

rem 启动
uvicorn app:app --host 127.0.0.1 --port 8000 --app-dir src/safety_backend
```

打开 http://127.0.0.1:8000/docs 可交互调试九个接口。macOS / Linux 用 `bash scripts/run.sh`。

## 演示话术（5 条）

1. **跑一笔干净业务**：选 `CS-0001` → 三步走通 → 生成待确认交接草稿 → 引用 K26/K27。
2. **跑一笔脏数据**：选缺照片元数据那笔 → 卡在「资料不足」转人工，不猜补、不销项。
3. **版本冲突**：选有两版记录那笔 → 两版并列展示，提示「需总监裁定」，不合并。
4. **越权请求**：用不在授权范围的编号调接口 → 返回 403 并写审计。
5. **问知识库**：「交接要包含什么才算完成」→ 回答末尾附引用条目与来源；检索不到就直说没有。

## 相对课堂 demo 的增量

- **把能力组合成业务闭环**：不只是会调模型，而是「谁在什么条件下能推进到哪一步」。
- **规则优先、模型补缝**：模型不进入判定路径，只出带引用的草稿。
- **人工卡点是真的卡点**：未确认的交接单导不出；这条曾被测出「只写在文档里」，修复后复测通过。
- **审计六字段**：任何一次输出可回溯到来源条目、数据版本、命中规则、模型建议、人工改动、签核人。

## 已知限制

1. **模型层未接生产模型**：当前以规则 + 人工形态交付，`/api/health` 返回 `degraded:true`；接入后须重跑异常集与回放集。
2. 回放集 100 笔为合成样本，真实脏数据比例未知，须试点期以实际台账校正。
3. 单机 JSON 存储在并发写入下有覆盖风险，试点 20 人以内可接受，扩面需换存储。
4. 主编号来源、接口写回能力、升级时限、审批矩阵等 5 项待客户确认。

## 红线

不自动销项 · 不判定安全合格 · 不写业务系统 · 不覆盖原始记录 · 不借用账号 · 不接未授权接口。
重大危险作业现场发现即人工处置。
