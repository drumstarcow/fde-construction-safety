# 施工隐患与整改闭环 · 协同助手

> FDE（Forward Deployed Engineer）训练项目：从业务挖掘到构建交付的完整一单。
> 课程：《开源创新思维》微专业期末项目 · 指导老师：祝欣蓉

## 这是什么

客户「远筑工程」的真实痛点不是"想用 AI"，而是**凭证链断了**：

- 整改照片对不上原隐患，巡查员反复跑现场核对
- 照片缺时间与位置，同一隐患多人上报形成重复工单
- 分包按上传照片算"完成"、监理按现场复查算"完成"，两套口径导致返工

本项目做的是**协同助手**：围绕一笔业务，核对来源、生成待人工复核的交接清单。
**不自动批准、不写入业务系统、不判定安全合格。**

## 核心设计：规则先做，模型补缝

确定性规则负责关联、去重、版本校验——命中即出结果，不经过模型；
模型只做两件事：疑难记录的相关性判断、交接草稿文本生成。模型输出永远是「建议」，不参与任何判定。

为什么需要模型：需要「字段不规整也能判断相关」的能力，规则写不出来；但正因为会错，所以只出草稿、不出结论。

## 红线

不自动销项、不判定安全合格、不写业务系统、不覆盖原始记录、不借用账号、不接入未授权接口；
重大危险作业现场发现即人工处置。

## 已知限制

1. 主编号来源、照片存储与关联字段待客户确认
2. 现有接口只读，是否存在写回能力待核实
3. 真实环境的照片缺时率与重复工单率未测量
4. 模型层尚未接入生产模型，当前实现为规则 + 降级路径
